# サマリー

## 目的

従来型のLinux Webアプリ構成をAWS上に構築し、OS・ミドルウェア・ストレージ・監視を一連の運用として説明できるようにすることを目的としました。マネージドサービスへの段階的な移行に向け、最初の基盤となるDay 1を実装しています。

## 実施内容

RHEL EC2上にApache、Tomcat、PostgreSQLを配置しました。Apacheが受けたHTTPリクエストをTomcatへ転送し、JSPがPostgreSQLのテーブルを読み取ります。DBデータは追加EBSに置き、共有ファイルにはEFS、成果物とログの保存にはS3を使用しました。

管理にはSSMを使い、アプリの確認もポート転送経由で行いました。CloudWatchへログとOS指標を送り、CPU・メモリ・ディスク・EC2状態の基本アラームを設定しました。

## 確認した成果

1. ブラウザーでDB由来の成功メッセージを確認しました。
2. OS更新後に再起動し、新カーネル、サービス自動起動、EBS/EFSマウント、DBデータの保持を確認しました。
3. CloudWatchで4ロググループの実イベントとメモリ・ディスク指標を確認しました。
4. EC2の正常停止後、DB用EBSのスナップショットがcompletedとなることを確認しました。

## 説明できる技術領域

| 技術領域 | 説明できる内容 |
|---|---|
| Linux運用 | dnf、systemctl、SELinux、firewalld、ログ・マウントの確認 |
| AWS基盤 | サブネットとルート、SG、SSM、EC2ロール、EBS/EFS/S3の使い分け |
| Web構成 | Apacheのリバースプロキシ、Tomcat/JSP、JDBCとDB認証 |
| 運用設計 | 監視指標、アラーム、再起動後検証、停止と保存料金の関係 |

## 制約と次の改善

EC2は1台で、WebとDBを同居させています。冗長化・HTTPS・負荷試験・バックアップからのリストアテストは本段階では実施していません。次の段階ではAuroraへのDB分離とロードバランサー連携を検討します。

## レビュー時の案内

構成は[設計判断](design.md)、実測は[検証結果](verification.md)、ソースは[構築スクリプト](../scripts/)から確認できます。作業完了時点のEC2は停止済みです。継続検証用に保存領域を保持しており、全リソース削除完了という状態ではありません。
