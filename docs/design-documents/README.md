## この文書の読み方

- **実測・実装済み**：作業記録、公開コード、要約証跡に根拠がある内容。
- **整理要件**：今回の学習目的と実績を基に、設計演習用に文章化した要件。構築前に顧客と合意した要件を意味しない。
- **未定義／未実施**：数値や実績を補わず、そのまま残した項目。
- **改善案**：今後の検討事項。現在実装済みの設定と区別する。

Day 1〜4を同時に常時稼働させる設計ではありません。Day 1の基盤・保存データを残し、Day 2〜4の検証用構成を段階ごとに作成・削除しています。最後の再現検証時点では、EC2は停止、Day 3/4の追加分は削除済みです。Day 2の対象割り当てのないBackupプランと、元EBS・EFS・スナップショット・S3等は保持しています。

## 根拠資料の優先順位

1. 実行結果・要約証跡：何を検証できたかを判断する根拠。
2. 対象段階のコンソール／Terraform実施記録：その時点の構成と修正・制約。
3. 公開コード：再実行時の設定値・処理順。公開向けの値置換と後日の修正を含む。
4. 本設計書：上記を横断して整理した説明。実測やコードにない保証を追加しない。

設定を再実行するときは、文書の転記値だけでなくリンク先のコードと実行計画を確認します。アカウントID、リソースID、ARN、メールアドレス、鍵・パスワード、state、plan、実値のtfvarsは非公開の実行台帳で管理します。

## 実務へ持ち込む際の確認事項

この構成をそのまま本番環境へ適用しません。利用者認証、外部公開とTLS、DB分離、可用性目標、RTO/RPO、処理量・応答時間、監査、秘密情報管理、運用体制、予算を顧客と合意し、設計・試験を更新する必要があります。職務上の上流工程参画実績ではなく、設計書作成と説明のための個人学習成果物として提示します。
