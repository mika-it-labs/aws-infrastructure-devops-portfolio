# 運用・終了手順

## Terraform化後の操作

IaC管理へ移行後は、起動・停止・構成変更を[Terraform手順](../terraform/README.md)で実施します。以下は元のDay 1操作を説明する資料です。手動変更を行った場合は、次のplanで差分を確認してください。

## 検証後の停止

1. アプリ確認とログ回収を終え、ポート転送セッションを終了します。
2. 初期更新の短縮に一時使用したUnlimitedはStandardへ戻します。
3. `Stop-Day1.ps1` で今回のEC2だけを停止します。
4. AWS APIでInstanceStateがstoppedであることを確認します。
5. DB用EBSのボリュームIDを照合してスナップショットを作成します。
6. completedを確認し、ローカル台帳に記録します。

Stopスクリプトは停止要求だけを行います。スナップショット取得と完了確認は別操作です。今回の実行では正常停止後のボリュームから取得しました。復元テストは行っていません。

## 次回の再開

台帳とAWSのリソースタグを照合してEC2を起動します。SSM Online、サービス、EBS/EFSのマウント、DBのデータを再確認します。パブリックIPv4は再起動ではなく停止・起動で変わり得るため、固定IPに依存せずSSMを利用します。

## 問題の切り分け

| 症状 | 最初に見る場所 |
|---|---|
| SSMに接続できない | EC2状態、専用ロール、SSM Agent、Internet Gatewayへの経路 |
| HTTP 502/503 | httpd error_log、Tomcat状態、8080待受、SELinux設定 |
| JSPでDB接続に失敗 | PostgreSQL状態、5432待受、pg_hba.conf、設定ファイルの所有者・権限 |
| 再起動後にDBが起動しない | findmnt、fstabのUUID、ボリュームの接続状態、SELinuxラベル |
| EFSをマウントできない | マウントターゲット状態、2049のSG、NFSクライアント、到達先IP |
| 監視データがない | Agent状態・設定・ログ、ロール権限、メトリクス出現までの反映時間 |

## 最終日の削除順序

以下は手順であり、削除済みという実績ではありません。専用VPC・タグと台帳を照合し、他の環境を削除対象に含めないようにします。

1. 必要な成果物を回収し、課金・保存要件を確認。
2. EC2を終了し、追加EBSが残ることを確認して、不要なら削除。
3. 不要なEBSスナップショットを削除。
4. EFSのマウントターゲットを削除し、完了後にファイルシステムを削除。
5. 今回のS3バケットのオブジェクトを削除してからバケットを削除。バージョニングを追加した場合は全バージョンも確認。
6. CloudWatchアラーム・ロググループを削除。
7. EC2インスタンスプロファイルからロールを外し、専用プロファイル・ポリシー関連付け・ロールを削除。
8. ENIの解放を確認後、専用SG、ルート関連付け、サブネット、ルートテーブル、Internet Gateway、VPCの順に依存関係を解消。
9. 予算通知はアカウント全体で共有しているため、他の学習にも必要か判断して保持・削除。
10. リージョンごとの残存リソースと、遅れて反映される請求を確認。

AWS Backupの復旧ポイント等を後日作成した場合は、その保持分も確認します。EC2停止だけで全課金がなくなるわけではありません。
